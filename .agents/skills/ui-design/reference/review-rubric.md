# 视觉评审 rubric（Critic 唯一评判标准）

> 评审者只看截图。每条都要落到「哪个区域 / 看到什么 / 为什么廉价 / 怎么改」。
> 报告问题优先于夸好；没问题的维度直接给高分跳过，不要凑数。

## 0. 一票否决：像不像 AI 做的

- **紫蓝渐变 / 大圆角卡片 / 三张等宽功能卡 / emoji 当图标** —— SaaS 套路四件套，命中即 P1。
- **没有焦点**：所有区块视觉重量相同 → 层级塌了。一屏只能有一个主角。
- **范式偷懒**（多方案对比时一票否决）：几个方案的布局、层级、控件类型完全一致，只换了色板/圆角/壁纸
  → 直接判定无效探索，要求重回阶段 1 以**交互范式**为轴重做（先看组块方式、再看信息密度、最后才看配色）。
- **模板感对称**：三等分栅格 + 居中堆叠 + 到处同样 padding。
- **装饰性玻璃/模糊/发光**出现在高频操作面上（不是弹层/导航这种本该浮起的表面）。
- **文字像 filler**：句子过长、字号小、行高挤、没有节奏（连续几段同一字号同一颜色）。

## 1. 层级 hierarchy（0–10）

- 第一眼落在哪？说不清 = P0。
- 标题 / 正文 / 辅助文字是否**至少差 3 倍**（尺寸、字重、灰阶任一维度组合）？
- 有无「两级看起来一样」的标题？有无 4 级以上层级（超过 3 级就该收）？
- 主操作是否与次操作在形状/填充上明确区分？

## 2. 间距与节奏 spacing_rhythm（0–10）

- 相邻元素是否共享同一套间距节奏（8/12/16/24…），还是各处随手 7px、9px、13px？
- **成组 vs 断组**：组内间距应明显小于组间距（看不出分组 = P1）。
- 容器内边距与兄弟容器是否一致？同类卡片是否同 padding？
- 边缘留白是否被挤压（文字贴边、按钮贴卡边）？
- 密集工具型界面：行高/控件高度是否统一，还是混着几种高度？

## 3. 排印 type（0–10）

- 是否只用一套字族体系（无衬线 + 等宽，各自有明确职责）？混排多个无衬线 = P1。
- 标题是否用了该字族的上限重量（粗体标题却用 500/600 是常见缺陷）？
- 大标题有无做光学字距（-0.02em 左右）？正文行长是否可读（中文 18–34 字/行）？
- 数字是否等宽对齐（表格/KPI 场景）？
- 大小写与标点是否一致（同一屏混用 Title Case 与 sentence case = P2）。

## 4. 色彩 color（0–10）

- 主色是否只承担**一种语义**（强调/进度/错误各有专色，别混用）。
- 灰阶是否中性、有无「脏灰」（在冷背景上用暖灰，或反之）。
- 正文对比度：小字（<16px/常规重）≥ 4.5:1，≥24px 或 ≥15.5px 粗体 ≥ 3:1。
  **用肉眼判断明显吃力的灰字，直接 P0**（这是本仓库最常犯的问题）。
- 有无「为好看而加」的第二第三强调色？一个界面 >1 个高饱和彩色通常是 P1。
- 深色模式下有无纯黑背景 / 纯白文字（应带色相偏移）。

## 5. 表面与克制 restraint（0–10）

- 卡片是否只靠**一个**区分手段（阴影 或 描边 或 底色），还是三样全上？
- 阴影是否成体系（少数几档、有方向感），还是随手 `0 0 10px rgba(0,0,0,.1)`？
- 圆角是否成阶梯（小组件 < 卡片 < 弹窗），还是全屏一个值 / 全屏乱值？
- 有无多余分割线（能用留白分组就别画线）。
- 图标风格是否统一（线性 or 面性，别混），尺寸是否落在几个固定档位上。

## 6. 状态与可用性（截图能看到的范围）

- 空状态是否只有一句「暂无数据」（应是能引导下一步的设计）。
- 长文本是否会被截断/换行打乱布局（看现有文字是否已贴破边界）。
- 窄屏/横向挤压下会不会崩（若给了多张尺寸图，逐张评）。
- 禁用/加载/错误态是否有视觉表达（看不到就要求补）。

## 7. 输出纪律（评审者必须遵守）

- findings ≤ 8 条，按 severity 排序，每条必须 `region` + `fix` 具体到可执行。
- 不许出现「建议增加对比度/更现代/优化间距」这类无 region 无数值的句子。
- 若某维度确实好，给分并在 summary 里一句带过，不编造问题。
- `looks_like_generic_ai` 是布尔：命中第 0 节任一条即 true。
